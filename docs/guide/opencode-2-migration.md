# OpenCode 2 切换实施与验收

## 范围与决策

- 分支：`codex/migrate-opencode2`。
- 基线：OpenCode 1.18.34；目标：官方 `@opencode/cli@2.0.27`，禁止浮动版本。
- 开发环境切换，不做 V1 历史数据库兼容迁移。V2 使用独立状态目录；必要时清空旧会话关联，保留可继续使用的账号、智能体、模型配置与工作文件。
- 保留平台的身份认证、用户隔离、执行队列与调度。V2 协议集中转换为平台会话视图，避免浏览器直接访问执行容器。
- 本次不制作或验收 Linux x86_64 离线发布包；离线交付需要以 V2 为新基线重新构建和验收。

## 阶段与通过条件

1. **运行基线**：构建固定版本；验证非 root、只读根目录、独立状态、认证、配置加载、模型与工具目录；失败则不切换现有服务。
2. **协议改造**：分页会话/消息、模型与智能体选择、异步收件箱、表单、权限、停止、事件和完成判定；增加行为测试。移除 V1 专用权限修补流程。
3. **隔离集成验证**：真实 V2 容器配合确定性模型/MCP 服务，覆盖聊天、连续对话、附件、工具、技能、MCP、协作、权限同意/拒绝、表单、取消、分支、调度、重启和用户隔离。运行类型检查、API/seed 测试及网页构建。
4. **本地切换**：停止旧任务写入，更新本地镜像配置并重建服务；核对旧会话关联处理、健康状态、页面和真实模型。明确记录本地验证与离线 x86 交付的不同范围。

## 上游依据

- [官方迁移说明](https://opencode.ai/v2/docs/migrate-v1/)
- [官方 API](https://opencode.ai/v2/docs/api)
- [官方 CLI](https://opencode.ai/v2/docs/cli/)

V2 使用 `/api/*` 接口、`data` 包装和游标分页；提示提交到收件箱，不能将 HTTP 接受视为执行完成。V2 权限使用 `action/resource/effect`，`task` 对应 `subagent`，`bash` 对应 `shell`；提问改为结构化表单。受管配置必须验证实际生效，不能只通过 JSON 检查。

## 实现变化

- `opencode-v2.ts` 集中处理 HTTP、分页、消息、事件、表单与错误。平台仍负责身份认证、授权、队列和状态持久化；浏览器不连接执行容器。
- V2 固定 Basic 用户名 `opencode`，密码仍每用户独立生成。容器命令改为 `opencode2 serve`，数据、缓存与状态均进入 `/state/v2/`；非 root、只读根目录和挂载范围保持原约束。
- 提示先进入 V2 收件箱。仅持久化的 `idle` 结果可结束执行，模型单步结束不能作为任务完成。提示使用稳定消息 ID；停止时删除尚未投递的收件箱项目，并中断当前任务及其子会话。
- 会话权限通过 V2 PATCH 替换，移除 V1 的空维护消息修补逻辑。协作默认拒绝，仅放行获配的子智能体。工作目录之外的读写保留审批；V2 拒绝工具授权会结束本轮并报告失败。
- 表单转为现有提问页面，保留标题、问题正文和选项值；回复按字段类型转换。外部客户端专用表单不在当前网页支持范围内。
- MCP 转为 `mcp.servers` 结构并显式禁用 Code Mode，维持逐项工具展示和智能体授权。子任务深度移到 `experimental.subagent_depth`。受管配置版本升级会生成新快照。
- 启动不只检查 HTTP 200，还等待并核对实际智能体目录，避免 V2 初始化期间把空目录误判为已就绪。
- 无新增 Prisma migration、环境变量或种子数据。旧的 V1 探针保留为历史资料，不能用于当前版本验收。

## 已有开发实例切换

适用条件：接受删除全部旧会话和执行记录；已有账号、智能体、模型配置、用户工作文件仍需使用。历史保留是硬性要求时，不得执行此流程，应另做 V1 到 V2 历史迁移验证。

1. 在新分支完成构建与隔离验收，参考[验收脚本](../../scripts/opencode2-validation/README.md)。镜像标签必须固定，不能复用 V1 标签。
2. 确认没有正在执行、排队或等待回答的任务。可先进行停写备份：

   ```bash
   python3 scripts/opshelper.py backup --output /absolute/private/backup-before-v2
   ```

   备份包含数据库、业务目录、配置和原部署环境文件；它包含密钥，保存在仓库之外或被忽略的私有目录。备份后服务保持停止。同时保留 V1 应用和运行时镜像，避免构建覆盖唯一旧标签。

3. 将 `.env` 的 `OPENCODE_DOCKER_IMAGE` 设为 `opshelper/opencode-runtime:2.0.27`，应用与 worker 指向本次验证过的镜像。先预览，再明确执行：

   ```bash
   python3 scripts/opencode2-cutover.py
   python3 scripts/opencode2-cutover.py --discard-history
   python3 scripts/opshelper.py up
   ```

   自定义部署可用 `--env-file` 和 `--compose-file` 指定同一份配置。切换脚本验证挂载与运行时版本，停止平台入口，检查未完成任务，按部署数据挂载识别并移除旧用户容器。数据库事务删除会话/执行与调度历史、暂停已有计划、重置容器和配置状态，启动后重新发布受管配置。**不要运行 bootstrap 或 seed。**

4. 验证 `/health`、用户配置就绪、容器版本、登录和新会话；用实际模型执行一次工具调用并检查最终成功状态。确认旧会话不再显示、原工作文件仍在。原计划会被暂停，逐项检查后再启用。

切换标记保存在 `data/config/.opencode2-cutover.json`，随业务备份保存；重复运行脚本会直接退出，不清空 V2 新会话。旧 V1 `/state` 文件保留但不再读取。账号和模型密钥不会被重置。

## 中止与恢复

- 镜像版本不匹配时，脚本不停止服务、不删除数据；先纠正配置。
- 发现未完成任务时，服务保持停止但历史未删除。恢复 V1 镜像配置并启动，结束任务后重新切换。
- 清理完成后不能只换回 V1 镜像并继续使用 V2 平台数据。需要回退时，使用原版本代码、完整旧镜像和切换前备份，按[备份恢复](backup-restore.md)恢复到新的独立数据目录；不要混合两个版本的数据库和状态目录。
- 没有切换前备份时，已删除的平台会话与执行记录无法恢复；旧 V1 状态目录本身不能重建完整平台关联。

## 验证与边界

本分支验证包含类型检查、API 单元测试、seed 测试、Prisma schema 校验、Web 生产构建，以及 29 项独立环境集成验收。隔离测试使用真实 V2 容器与本地确定性模型/MCP；覆盖队列、流式输出、文件、技能、协作、权限、提问、取消、分支、隔离、重启、调度和配置撤销。浏览器验收检查了提问正文、提交答案与最终展示。

本地切换另做真实模型与 shell 调用验收；具体部署记录、截图、备份和报告只保存在被忽略的本机目录。测试脚本可重新生成报告。备份校验通过不等于已经进行恢复演练。

以上不代表 Linux x86_64 离线安装、旧离线升级包兼容或生产现场验收通过；此三项均不在本次本地开发切换的验证范围内。
