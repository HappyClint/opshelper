# opshelper 故障排查

先记录发生时间、用户账号、页面提示、对话或计划名称、执行状态，以及协作过程中的排障编号。管理员再核对用户、Agent 分配、配置代次和容器日志。不要用重新发送、重建或删除掩盖尚未核对的执行状态。

## 登录或页面打不开

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 账号或密码错误 | 核对账号拼写，确认账号启用 | 管理员在用户管理中启用账号或重置密码 |
| 登录后又回到登录页 | 检查浏览器 Cookie、入口协议/域名是否变化 | 从同一管理员提供的入口重新登录；仍失败时检查 API 日志和会话配置 |
| 整站打不开 | 访问 `/health`，再检查 nginx、web、api 和 PostgreSQL | `/health` 只代表 API；按失败服务查看日志和依赖状态 |
| 页面能开但定时任务不登记 | 检查 worker 是否运行及其日志 | 恢复 worker；按默认配置，超过 2 分钟的漏点记为跳过，不会补跑 |

## 没有智能体或不能发送

“管理员尚未给你分配智能体”表示当前没有可见的已装配 Agent。管理员应依次确认 Agent 已启用、检查通过、已分配给该用户，且用户配置为“已就绪”。

“运行环境尚未就绪”或配置更新提示通常对应以下状态：

- 等待当前任务：等待当前顶层执行结束；
- 正在撤销/正在装配：等待处理完成，不要反复保存分配；
- 已冻结：读取冻结原因，修复模型、Agent 依赖、容器或实际清单问题，再在“用户分配”点“重新装配”。

若已应用代次小于目标代次，或实际 Agent 清单与期望清单不同，不应让用户继续新任务。停用或撤销 Agent 后，依赖它的定时任务自动暂停是预期行为。

## 对话一直排队、等待或中断

| 页面状态 | 含义 | 处理 |
| --- | --- | --- |
| 排队中 | 同一用户已有顶层执行；定时任务和手工任务共用队列 | 等待前序任务完成，不要重建第二个容器 |
| 等待你的回答或确认 | OpenCode 正等待问题答案或单次工具授权 | 回到对应对话提交答案，或选择“允许一次/拒绝” |
| 执行失败 | 已得到明确失败或超时结果 | 阅读错误和容器日志，修复原因后再发新任务 |
| 已取消 | 用户停止，或暂停/依赖变更取消了尚未开始的定时执行 | 确认触发原因，需要时重新运行 |
| 执行状态无法确认 | 发送或停止结果无法安全判断，用户执行槽位被冻结 | 点“重新核对状态”；核对完成前不要改写后重复发送 |

网页短暂断线后会重新读取对话和执行状态。发送失败提示要求“网络恢复后再次发送”时，保留原输入和附件再次操作，前端会沿用同一请求标识；不要先修改内容，否则会被视为新请求。

执行中点发送会正常进入个人队列。若队列长时间不动，管理员检查当前执行是否停在问题/权限确认、租约是否仍有效、API 执行循环和用户容器日志。

## 容器无法启动或不能操作

1. 在“用户分配”确认配置为“已就绪”；冻结时先处理冻结原因。
2. 在“容器管理”查看日志，关注镜像启动、挂载、运行时密码和 OpenCode 健康检查错误。
3. 确认当前没有活动执行或待恢复状态；这些状态会拒绝停止、重启、重建环境和移除容器。
4. 生命周期操作提示正在进行或 429 冷却时，等待当前操作/冷却结束后重试。
5. 普通启动仍失败且数据已备份时，可使用“重建环境”加载当前镜像；它保留 workspace 和 state。

“移除容器”用于丢弃当前 Docker 对象，保留用户文件、OpenCode state 和受管快照；下次任务会按当前配置重建。删除用户账号才会删除该用户的数据目录和业务记录，应先完成整套备份。

容器空闲后自动停止属于正常行为。聊天或定时执行会按需唤醒；启用“保持容器运行”可免于空闲回收。

## 文件问题

| 提示或现象 | 原因与处理 |
| --- | --- |
| 上传失败或 413 | 单个上传文件当前限制 10 MiB；缩小或拆分文件 |
| 无法预览或内容过大 | 文本预览/编辑限制 2 MiB；不可预览格式请下载查看 |
| 文件已被其他进程修改 | 智能体或另一个页面已修改文件；先核对内容，再决定是否二次保存覆盖 |
| 目标已存在 | 改名或选择其他目录，系统不会静默覆盖已有目标 |
| 路径被拒绝 | 只能访问当前用户的 `/workspace`，不能用绝对宿主路径、`..` 或符号链接越界 |
| 结果文件链接提示不存在 | 文件已被移动或删除；从“我的文件”搜索相关输出目录并核对执行记录 |

删除文件和文件夹不可恢复；排查前不要清理 `chat-uploads`、`outputs` 或用户目录。

## 定时任务没有执行

先打开任务详情查看状态原因和最近执行记录：

- “已跳过”且显示漏点：按默认配置，worker 处理时已晚于计划时间超过 2 分钟，系统不补跑；
- “已跳过”且显示重叠：同一计划上一次执行仍未结束；
- “已暂停”：可能由用户主动暂停、用户停用、Agent 被撤销/停用/检查失败，或配置冻结触发；
- “等待处理”：执行正在等待用户回答或工具确认，打开对应对话处理；
- “状态待核对”：打开对应对话执行“重新核对状态”。

恢复任务会重新校验 Agent 分配、附件、模型和时间。按钮不可用时先修复依赖并等待用户配置“已就绪”。暂停任务不能立即运行；完成的一次任务需要编辑到未来时间后再次启用。

任务到点只由 worker 写入数据库，实际模型执行由 API 循环领取并按需启动用户固定容器。因此“有执行记录但一直排队”应检查 API/容器，“完全没有到点记录”应检查 worker 和计划的 `nextRunAt`。

## 模型或 Agent 检查失败

- 模型不可用：核对“模型连接”的 `baseURL`、API Key、模型 ID 和默认模型；保存后等待所有用户重新装配。
- Agent frontmatter 错误：确认 `agent.md` 有完整的 `---` 区块、名称、说明和非空正文，`mode` 使用 `primary`、`subagent` 或 `all`。
- 模型引用错误：使用已配置的完整引用，例如 `custom/<model-id>`。
- Skill 或脚本缺失：引用的 Skill 必须有 `skills/<名称>/SKILL.md`，脚本必须存在于 `scripts/`。
- 实际清单残留旧 Agent：保持冻结，确认旧容器停止和受管快照可替换后执行“重新装配”。

Agent 修改与普通模型更新会等待当前顶层执行结束；撤销、停用和用户停用进入更严格的撤销流程。不要通过直接改用户 workspace 中的 OpenCode 配置绕过管理员目录，运行时不会把它作为受管 Agent 来源。
